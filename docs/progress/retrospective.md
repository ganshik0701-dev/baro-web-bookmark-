# 8주 회고

크롬 북마크를 아이콘 그리드로 보여 주는 Windows 앱을 8주 동안 만들어 [v0.1.0](https://github.com/ganshik0701-dev/baro-web-bookmark-/releases/tag/v0.1.0)으로 냈고, 다른 PC에 설치해 쓰는 것까지 확인했다. 주차별 내용은 [PROGRESS.md](../../PROGRESS.md)와 week 파일([00](week-00.md)~[08](week-08.md))에 있다.

## 잘된 것

- 명세를 먼저 고치고 코드를 맞추는 순서를 끝까지 지켰다
- "고쳤다"와 "확인했다"를 나눴고, 확인에는 대조군을 붙였다(일부러 실패할 요청, 고치기 전 코드와 비교)
- 측정·점검은 가짜 데이터와 읽기 전용 쿼리로 해서 운영 DB를 지켰다
- 사람이 확인할 일은 한 단계씩 끊어 가서, 놓친 것을 바로 가려냈다
- **가장 뿌듯했던 순간:** 다른 PC에서 릴리스를 받아 설치했을 때 북마크 112개가 그대로 뜬 순간

## 어려웠던 것과 배운 것

- **늦게 찾은 한계: PC 한 대 기준.** 크롬 북마크를 PC마다 바뀌는 id로 짝지어, 다른 PC에서 동기화하면 그 PC 북마크로 바뀐다. 외부 id를 키로 쓸 때는 "언제 바뀌나"를 처음에 물어야 한다([week-08](week-08.md))
- **설치본 보안은 기본값이 아니다.** 디버깅 통로와 창 이동은 직접 막고, 띄워 본 뒤에야 믿을 수 있었다
- **도구가 결과물을 바꾼다.** 개발 실행이 빌드 결과를 덮어쓴 일처럼, 쓰기 직전에 다시 확인해야 한다
- **가장 막혔던 순간:** 메모리 부족으로 작업이 자주 끊긴 것. 기준을 정하고 작업을 나누고, 앱 대신 SQL을 쓰는 식으로 방식을 메모리에 맞춰 풀었다
