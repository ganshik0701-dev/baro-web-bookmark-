## 간격·모양

값은 모두 `apps/desktop/src/renderer/src/styles/tokens.css`에 있다. 아래 '어디를 고치면 무엇이 바뀌는가' 표 참고.

- 모서리: 아이콘 타일 18px, 카드 14px, 모달·첫 동기화 카드·로그인 미리보기 18px, 큰 버튼·입력칸 12px, 사이드바·검색·정렬·설정 컨트롤 10px, 사이드바 목록 항목 8px
- 사이드바 248px(접으면 64px), 모든 화면에서 같은 자리(로그인·첫 동기화는 사이드바 없음)
- 본문 안쪽 여백 22px(위아래)·32px(좌우)

## 그리드

타일 크기와 열 수는 **그리드 영역의 폭**(창 − 사이드바 − 좌우 여백)으로 정한다. 사이드바가 생겨 창 너비로는 맞지 않게 됐다(1280px 창에서 그리드 영역은 약 968px).

| 그리드 영역 폭 | 열 | 아이콘 |
| --- | --- | --- |
| ~640px | 6 | 56px |
| 641~1040px | 8 | 64px |
| 1041px~ | 10 | 72px |

- 1280×800 창은 8열 64px다(보드는 8열 62px. 62px는 그린 근삿값이고 구현은 이 표를 따른다). 최소 창 800px이면 그리드 영역 약 488px → 6열
- CSS 변수는 `@media` 조건에 쓸 수 없다. 기준점·열 수·아이콘 크기는 `tokens.css`에 두고 JS가 읽는다. 폭은 그리드 영역에 `ResizeObserver`를 걸어 잰다
- 섹션: '고정됨'(없으면 숨김) + 아래 섹션. 섹션 제목은 Hahmlet 16px 700
- 가상 스크롤은 **8주차 1,000개 측정 결과를 보고 필요할 때만** 넣는다

## 좁은 창 (최소 800×560)

시안은 1280×800 하나뿐이다. 좁은 창 규칙은 이 절에만 적는다(2026-09-28). 아래 폭은 토큰으로 계산한 값이고 실제 앱 확인 때 잰다.

| 확인할 것 | 사이드바 편 채 800px | 규칙 |
| --- | --- | --- |
| 그리드 | 영역 약 488px → 6열 56px (접으면 약 672px → 8열 64px). 실제 앱(2026-09-29): 편 채 471px 6열, 접으면 655px 8열(스크롤바 자리 15px를 뺀 값) | 그리드 표 그대로. 스크롤바 자리는 늘 비워 둔다(`scrollbar-gutter: stable`, 스크롤바가 생기고 사라지며 열 수가 흔들리지 않게) |
| 검색 + 정렬 | 정렬 약 220px(가장 긴 항목 "자주 방문순 · 최근 30일"), 검색창 약 256px | 한 줄에 둔다. 검색창이 줄어든다(`min-width: 0`) |
| 설정 카드 | 카드 안쪽 약 444px, 토큰 원본(48자) 약 360px + [복사] 약 70px | 경로·토큰 원본은 **한 줄 말줄임 + 전체는 `title`**. 카드 폭은 넓은 창에서도 최대 720px |
| 모달(540·560px) | 창 안쪽 약 736px | **고정 폭 + `max-width: 100%`**, 높이가 넘치면 **모달 안에서 스크롤**(`max-height: 100%`). 560px 높이에서 대량 삭제 모달(예시 5개)이 약 480px로 빠듯하다 |
| 첫 동기화 카드(660px) | 좌우 60px 빼면 680px | 폭은 들어간다. 결과 화면이 높이를 넘치면 바깥 영역 스크롤 |
| 로그인 | 소개 400 + 72 + 미리보기 330 → 넘침 | 900px 이하에서 미리보기를 숨긴다(기존 규칙) |
| 사이드바 세로 | 로고·추가·목록 3개·아래 칸 합 약 360px | 560px 높이에 들어간다 |

사이드바 접기는 편의 기능이다(위 표대로 편 상태로도 깨지지 않는다). 규칙은 docs/01-spec.md '사이드바 규칙'의 '접기'.

## 규칙

- 아이콘 타일은 두 가지이고 크기·모서리가 같다(파비콘이 있든 없든 줄이 흔들리지 않게)
  - 파비콘: 흰 타일(`--surface`, 1px `--border`) 가운데에 파비콘을 타일의 50% 크기로
  - 글자: 제목 첫 글자 + 도메인 해시로 고른 한 쌍(`--tile-N-bg` 배경, `--tile-N-fg` 글자). 파비콘을 불러오기 전과 실패했을 때
- 아이콘은 인라인 stroke SVG. 이모지 쓰지 않음
- 클릭 대상 최소 44px(사이드바 목록 항목 40px은 폭이 넓어 예외), 아이콘만 있는 버튼에는 `aria-label`
- 명도 대비 4.5:1 이상 (24px 이상은 3:1). 비활성 컨트롤은 요구 대상이 아니지만 `--text-subtle` 이상을 쓴다
- 실제 `<button>`·`<a>`·`<input>`+`<label>` 사용. div에 onClick 금지
- 그라데이션 배경, 왼쪽 테두리 강조 카드 같은 흔한 장식은 쓰지 않는다
- '확장 연결됨' 배지는 두지 않는다. 앱은 확장이 연결됐는지 알 수 없다(설정의 토큰 목록에 '최근 사용' 시각으로 대신)

## 어디를 고치면 무엇이 바뀌는가

여러 화면이 함께 쓰는 디자인 값은 **`apps/desktop/src/renderer/src/styles/tokens.css` 한 파일**에 있다.
다른 CSS·TSX 파일은 이 값을 `var(--이름)`으로 가져다 쓰기만 한다.

고치는 법: 이 파일에서 `--이름: 값;`의 값만 바꾸고 저장한다. `pnpm dev:desktop`이 켜져 있으면 바로 반영된다(그리드 기준점만 창 크기를 한 번 바꿔야 반영된다).
단위(`px`)는 지우지 않는다. 틀리게 쓰면 그 값만 무시되고 오류는 나지 않으니, 안 바뀌면 오타부터 본다.
