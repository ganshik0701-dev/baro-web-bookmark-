# 02. DB 설계

PostgreSQL(Supabase) 테이블 5개. 사용자 계정 자체는 `auth.users`가 관리한다.

```
auth.users ──1:1── profiles ──1:N── groups ──1:N── bookmarks ──1:N── visit_logs
                        └──1:N── api_tokens
```

## profiles (사용자 설정)

| 컬럼 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| id | uuid | PK, FK → auth.users.id | |
| email | varchar(255) | NOT NULL | Google 계정 이메일 |
| display_name | varchar(50) | NULL | Google 이름 |
| avatar_url | text | NULL | Google 프로필 사진 |
| sort_option | varchar(20) | NOT NULL, 기본 `created_desc` | created_desc / visits_30d / visited_desc / title_asc / custom |
| open_mode | varchar(10) | NOT NULL, 기본 `new_tab` | new_tab / same_tab |
| theme | varchar(10) | NOT NULL, 기본 `system` | light / dark / system |
| auto_sync | boolean | NOT NULL, 기본 true | 앱 시작 시 자동 동기화 |
| chrome_profile | varchar(50) | NULL | 마지막으로 고른 크롬 프로필 |
| last_synced_at | timestamptz | NULL | |
| created_at / updated_at | timestamptz | NOT NULL, 기본 now() | |

## groups

| 컬럼 | 타입 | 제약 |
| --- | --- | --- |
| id | uuid | PK, 기본 gen_random_uuid() |
| user_id | uuid | NOT NULL, FK → profiles.id ON DELETE CASCADE |
| name | varchar(30) | NOT NULL |
| position | integer | NOT NULL |
| chrome_folder_id | varchar(50) | NULL (동기화 매칭용) |
| created_at / updated_at | timestamptz | NOT NULL, 기본 now() |

제약: `UNIQUE(user_id, name)`

## bookmarks

| 컬럼 | 타입 | 제약 | 설명 |
| --- | --- | --- | --- |
| id | uuid | PK | |
| user_id | uuid | NOT NULL, FK → profiles.id ON DELETE CASCADE | |
| group_id | uuid | NULL, FK → groups.id ON DELETE SET NULL | NULL = 미분류 |
| title | varchar(100) | NOT NULL | |
| url | text | NOT NULL, CHECK (`url ~ '^https?://'`) | |
| normalized_url | text | NOT NULL | 중복 검사용 |
| icon_url | text | NULL | NULL이면 파비콘 서비스 사용 |
| source | varchar(15) | NOT NULL, 기본 `manual` | manual / app_sync / ext_sync / html_import |
| chrome_id | varchar(50) | NULL | 크롬 북마크 id |
| tags | text[] | NOT NULL, 기본 `{}` | 최대 10개 |
| is_pinned | boolean | NOT NULL, 기본 false | |
| position | double precision | NOT NULL | 사용자 지정 정렬 |
| click_count | integer | NOT NULL, 기본 0 | 누적 |
| last_visited_at | timestamptz | NULL | |
| created_at / updated_at | timestamptz | NOT NULL, 기본 now() | |

`position`은 실수형이라 드래그 시 앞뒤 값의 중간값(1.0과 2.0 사이 → 1.5)만 넣으면 한 행만 갱신된다. 간격이 좁아지면 전체 재번호.

## visit_logs (방문 기록)

| 컬럼 | 타입 | 제약 |
| --- | --- | --- |
| id | bigint | PK, identity |
| bookmark_id | uuid | NOT NULL, FK → bookmarks.id ON DELETE CASCADE |
| user_id | uuid | NOT NULL |
| visited_at | timestamptz | NOT NULL, 기본 now() |

'자주 방문순'은 최근 30일 기준이므로 MVP에 포함. 90일 지난 로그는 삭제한다.

```sql
SELECT b.*, COUNT(v.id) AS recent_visits
FROM bookmarks b
LEFT JOIN visit_logs v
  ON v.bookmark_id = b.id
 AND v.visited_at > now() - interval '30 days'
WHERE b.user_id = $1
GROUP BY b.id
ORDER BY b.is_pinned DESC, recent_visits DESC, b.click_count DESC;
```

느려지면 `bookmarks.recent_visit_count` 컬럼을 두고 하루 한 번 집계하는 방식으로 바꾼다.

## api_tokens (확장 전용)

| 컬럼 | 타입 | 제약 |
| --- | --- | --- |
| id | uuid | PK |
| user_id | uuid | NOT NULL, FK → profiles.id ON DELETE CASCADE |
| name | varchar(30) | NOT NULL |
| token_hash | char(64) | NOT NULL, UNIQUE (SHA-256) |
| prefix | char(8) | NOT NULL (목록 표시용) |
| last_used_at | timestamptz | NULL |
| created_at | timestamptz | NOT NULL, 기본 now() |

사용자당 최대 5개. 원본 토큰은 발급 응답에서만 보여주고 저장하지 않는다.
- 5개 제한은 트리거 `enforce_api_token_limit`(005)가 지킨다: INSERT 전에 그 사용자의 profiles 행을 `FOR UPDATE`로 잠그고 개수를 센다. 같은 사용자의 동시 발급은 이 잠금에서 줄을 서므로 6개째가 생기지 않는다. 넘으면 `P0001` 오류(메시지 `TOKEN_LIMIT_EXCEEDED`) → API가 409로 바꾼다
- `last_used_at`은 **5분 단위**로만 쓴다(마지막 값이 5분보다 오래됐을 때만 UPDATE). 확장이 연달아 요청해도 같은 행에 쓰기가 몰리지 않는다

## RLS·트리거·함수

- 5개 테이블 모두 RLS 활성화. 조건은 `user_id = auth.uid()` (profiles는 `id = auth.uid()`)
- API의 DB 접속: Drizzle로 직접 접속하되(Supavisor 트랜잭션 풀러, `DATABASE_POOLER_URL`), 요청마다 트랜잭션 안에서 `SET LOCAL ROLE authenticated`와 `set_config('request.jwt.claims', <검증한 claims>, true)`를 먼저 실행한다. 그래서 API 경로에서도 RLS와 `auth.uid()`가 PostgREST와 똑같이 적용된다. 모든 쿼리에 `user_id` 조건도 직접 붙인다(이중 확인)
  - 접속 계정(`postgres`)은 테이블 소유자라 역할을 바꾸지 않으면 RLS를 건너뛴다. 그래서 트랜잭션마다 `current_user`가 `authenticated`인지 확인하고, 아니면 쿼리 전에 실패시킨다
  - claims는 서명을 검증한 토큰에서만 만든다. 요청 바디·쿼리 값으로 만들지 않는다
  - 확장 요청(`baro_` 토큰)도 토큰 해시로 사용자를 확인한 뒤 같은 방식(`{ sub, role: 'authenticated' }`)으로 쿼리한다. 서비스 키는 쓰지 않는다
  - **예외 하나: 확장 토큰 조회.** 이때는 아직 누구인지 몰라 RLS로 찾을 수 없으므로, 트랜잭션에서 `SET LOCAL ROLE baro_token_resolver`로 바꾸고 `private.resolve_api_token(해시)`만 부른다. `current_user` 확인 가드는 같다
- 역할 `baro_token_resolver`(005): 로그인 불가, 테이블 권한 없음, 아래 함수 실행 권한만. PostgREST가 쓰는 역할(anon·authenticated)이 아니고 `authenticator`에도 붙이지 않아 REST API로는 쓸 수 없다. `postgres`에 부여해 API 연결이 이 역할로 바꿀 수 있게 한다
- 스키마 `private`(005): REST API가 노출하지 않는 스키마. 사용자가 부르면 안 되는 함수를 둔다
- 함수 `private.resolve_api_token(p_token_hash char(64)) returns uuid`: `security definer`, `search_path = ''`. 해시가 맞는 토큰의 `user_id`만 돌려주고(없으면 null) 다른 값은 내보내지 않는다. `last_used_at`을 5분 단위로 갱신. 실행 권한은 `baro_token_resolver`에만(Postgres 기본값인 PUBLIC과 Supabase 기본값인 anon·authenticated·service_role에서 모두 회수)
  - 인자가 `char(64)`여야 `idx_tokens_hash`를 쓴다. `text`로 비교하면 컬럼 쪽이 `::text`로 바뀌어 전체 스캔이 된다(EXPLAIN으로 확인)
- 트리거 `on_auth_user_created`: 첫 로그인 시 profiles 자동 생성(메타데이터에서 이름·사진 복사)
- 트리거 `set_updated_at`: UPDATE 시 `updated_at` 갱신
- 함수 `record_visit(bookmark_id uuid)`: `click_count + 1`, `last_visited_at` 갱신, `visit_logs` 삽입을 한 트랜잭션으로
- 트리거 `enforce_api_token_limit`: api_tokens INSERT 전 사용자당 5개 검사(위 api_tokens 참고)

## 마이그레이션 초안 (참고용, 실제 작성 시 검증할 것)

```sql
-- 001_init.sql
create table profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  email varchar(255) not null,
  display_name varchar(50),
  avatar_url text,
  sort_option varchar(20) not null default 'created_desc',
  open_mode varchar(10) not null default 'new_tab',
  theme varchar(10) not null default 'system',
  auto_sync boolean not null default true,
  chrome_profile varchar(50),
  last_synced_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

alter table profiles enable row level security;
create policy "own profile" on profiles
  for all using (id = auth.uid()) with check (id = auth.uid());

-- groups, bookmarks, visit_logs, api_tokens 도 같은 방식으로
-- (각 테이블: user_id = auth.uid())

create or replace function record_visit(p_bookmark_id uuid)
returns void language plpgsql security definer as $$
begin
  update bookmarks
     set click_count = click_count + 1,
         last_visited_at = now()
   where id = p_bookmark_id and user_id = auth.uid();

  insert into visit_logs (bookmark_id, user_id)
  select id, user_id from bookmarks
   where id = p_bookmark_id and user_id = auth.uid();
end; $$;
```
